### 1.2 Regras

| Regra | Comportamento |
|---|---|
| Papéis | `analista`, `gestor` e `administrador`. Sem token → `401 AUTH_UNAUTHENTICATED`. Papel fora da policy → `403 AUTH_FORBIDDEN_ROLE` |
| Token do administrador | `sub` e `role`, sem `escopoId`. Em `Auth:MockUsers`, o administrador não tem `NetworkId`; os outros papéis continuam com ele obrigatório. A validação do startup recusa as duas inversões |
| `ICurrentUser` | Ganha `IsPlatformAdmin`. `NetworkId` continua `Guid` e só pode ser lido quando `IsPlatformAdmin` é falso; para o administrador, lança `InvalidOperationException` (erro de programação) |
| TenantGuard | `[ValidateTenantScope]` libera o administrador. Para analista e gestor, nada muda. Campanhas continuam fechadas ao administrador pela policy `ManageCampaigns` |
| Escopo na leitura | Analista e gestor: rede diferente da do token → `403 SCOPE_FORBIDDEN`, também quando a rede só aparece ao ler o pai (`ScopeForbiddenException`) |
| Listagem de redes | Administrador: todas as redes. Analista e gestor: só a própria |
| Canais da loja | `channels` obrigatório, com ao menos um item, sem repetição, e só `Physical` ou `Virtual` (sem diferenciar maiúsculas) → senão `400 VALIDATION_ERROR`. No `PUT`, a lista substitui os canais habilitados: o tipo que sai fica `is_active = false`, o que volta é reativado na mesma linha (índice único `establishment_id + type`), o novo é inserido. A resposta lista só os canais habilitados, em ordem fixa (`Physical`, `Virtual`) |
| Reativação | Reativar região exige a rede ativa; reativar loja exige a região ativa (`422`, códigos abaixo). Produto exige a categoria ativa |
| Rede no corpo | `POST /regions` com `networkId` ausente ou `Guid` vazio → `400`. Antes, o `Guid` vazio caía no TenantGuard e voltava `403` |

### 1.3 Fora desta entrega (revisão da TS#9, pontos não bloqueantes)

- Catálogo global, sem rede, inativável por qualquer rede (ponto 5).
- Troca de `timeZone` da rede com campanhas existentes (ponto 7, liga-se à US-02.6).
- Esquema Bearer no documento OpenAPI.
- Organização de pastas (`Application/Ports`, `INetworkRepository` duplicado), validação duplicada em `InputValues` e `createdAt` sem `Z` (pontos 11 a 13).
- Alerta ao analista sobre o impacto da inativação na campanha (US-02.2 C3) e a decisão D7 do backlog sobre loja única inativada.
- Projeção local de usuários (US-02.5): o administrador entra só em `Auth:MockUsers`, como os outros papéis.

> **Divergência registrada:** a US-02.5 descreve o papel na projeção local como "analista ou gestor". A PR-15 exige um perfil administrativo. Esta spec segue a PR-15 e acrescenta `administrador`.

## 2. Contratos & Schemas (DTOs / Records)

Só os contratos que mudam. Rede, região, categoria e produto mantêm os contratos da TS#9.

```csharp
// Application/Authentication
public static class Roles
{
    public const string Analista = "analista";
    public const string Gestor = "gestor";
    public const string Administrador = "administrador";
}

public record UserAccount(Guid UserId, string Email, string Role, Guid? NetworkId);

public interface ICurrentUser
{
    Guid UserId { get; }
    string Role { get; }
    bool IsPlatformAdmin { get; }
    Guid NetworkId { get; } // lança para o administrador
}

// Application/DTOs/Organization
public record CreateEstablishmentRequest(Guid? RegionId, string Code, string Name, IReadOnlyList<string>? Channels);
public record UpdateEstablishmentRequest(string Code, string Name, bool? IsActive, IReadOnlyList<string>? Channels);
public record EstablishmentResponse(
    Guid Id, Guid RegionId, string Code, string Name, IReadOnlyList<string> Channels, bool IsActive, DateTime CreatedAt);

// Removidos: CreateChannelRequest, UpdateChannelRequest, ChannelResponse, IChannelService, ChannelsController.
```

### Códigos de regra

| Code | Mensagem | Quando |
|---|---|---|
| `REGION_NETWORK_NOT_FOUND` | Rede informada não encontrada | `POST /regions` com rede inexistente |
| `REGION_NETWORK_INACTIVE` | Rede informada está inativa | Criar ou reativar região em rede inativa. Substitui o uso de `CampaignErrors.NetworkUnavailableCode` |
| `ESTABLISHMENT_REGION_NOT_FOUND` | **Região informada não encontrada** | `POST /establishments` com região inexistente (US-02.1 C2) |
| `ESTABLISHMENT_REGION_INACTIVE` | Região informada está inativa | Criar ou reativar loja em região inativa. Substitui `ESTABLISHMENT_PARENT_UNAVAILABLE` |
| `PRODUCT_CATEGORY_NOT_FOUND` | **Categoria informada não encontrada** | `POST /products` com categoria inexistente (US-02.4 C2) |
| `PRODUCT_CATEGORY_INACTIVE` | Categoria informada está inativa | Criar ou reativar produto em categoria inativa. Substitui `PRODUCT_PARENT_UNAVAILABLE` |
| `PRODUCT_CODE_TAKEN` | **Já existe produto com este identificador** | Código duplicado (US-02.4 C3), inclusive quando o conflito é detectado pelo índice único |

Os demais (`NETWORK_NAME_TAKEN`, `REGION_NAME_TAKEN`, `ESTABLISHMENT_CODE_TAKEN`, `CATEGORY_NAME_TAKEN`) seguem como estão. `CHANNEL_PARENT_UNAVAILABLE` e `CHANNEL_TYPE_TAKEN` são removidos.

Mensagens de `400` novas: "Informe ao menos um canal do estabelecimento.", "Tipo de canal inválido. Use 'Physical' ou 'Virtual'." e "Os canais do estabelecimento não podem se repetir.".

## 3. Especificação do Endpoint / Serviço

Policies novas em `AuthorizationPolicies`:

- `ManageHierarchy`: `administrador`.
- `ReadHierarchy`: `administrador`, `analista` e `gestor`.

| Método | Rota | Policy | Escopo |
|---|---|---|---|
| `GET` | `/api/v1/networks` | `ReadHierarchy` | Administrador: todas. Demais: só a rede do token |
| `GET` | `/api/v1/networks/{networkId}` | `ReadHierarchy` | `[ValidateTenantScope]` (libera administrador) |
| `POST` | `/api/v1/networks` | `ManageHierarchy` | — |
| `PUT` `DELETE` | `/api/v1/networks/{networkId}` | `ManageHierarchy` | — |
| `GET` | `/api/v1/regions?networkId=` | `ReadHierarchy` | `[ValidateTenantScope]`; rede inexistente → `404` |
| `GET` | `/api/v1/regions/{id}` | `ReadHierarchy` | Rede da região conferida no serviço |
| `POST` | `/api/v1/regions` | `ManageHierarchy` | Sem TenantGuard |
| `PUT` `DELETE` | `/api/v1/regions/{id}` | `ManageHierarchy` | — |
| `GET` | `/api/v1/establishments?regionId=` | `ReadHierarchy` | Rede da região conferida no serviço; região inexistente → `404` |
| `GET` | `/api/v1/establishments/{id}` | `ReadHierarchy` | Rede da loja conferida no serviço. Devolve `channels` (US-02.1 C3) |
| `POST` | `/api/v1/establishments` | `ManageHierarchy` | — |
| `PUT` `DELETE` | `/api/v1/establishments/{id}` | `ManageHierarchy` | — |
| `*` | `/api/v1/categories`, `/api/v1/products` | `ManageCampaigns` | Sem mudança de escopo |

Respostas: `200`/`201`/`204` no sucesso; `400 VALIDATION_ERROR`; `401 AUTH_UNAUTHENTICATED`; `403 AUTH_FORBIDDEN_ROLE` ou `SCOPE_FORBIDDEN`; `404 NOT_FOUND` (id da URL ou pai da query); `422` com o `code` da regra.
