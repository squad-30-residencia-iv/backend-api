## 1. Contexto & Regras de Negócio

- O `POST /api/v1/auth/login` deixa de conferir a senha em `Auth:MockUsers` e passa a conferir na tabela `users`.
- E-mail é comparado sem diferenciar maiúsculas, depois de remover espaços nas pontas. A linha guarda o e-mail normalizado em minúsculas.
- Senha errada e e-mail inexistente respondem o mesmo `401 AUTH_INVALID_CREDENTIALS`. A resposta não diz qual dos dois falhou.
- A senha é gravada só como hash PBKDF2 com salt. Não volta em nenhuma resposta.
- Papel `administrador` fica com `network_id` nulo. `analista` e `gestor` exigem `network_id`. Não há chave estrangeira para `networks`.
- `Auth:MockUsers` continua na configuração só como carga inicial: se `users` estiver vazia, a subida grava esses usuários já com hash. Uma senha alterada no `appsettings` depois disso não muda a linha existente.
- Token, papéis, `escopoId` e o corpo do login (`token`, `expiresIn`, `message`, `profile`) permanecem os da US-02.5.

## 2. Contratos & Schemas (DTOs / Records)

O contrato HTTP não muda. A entidade nova:

```csharp
public class User
{
    public Guid Id { get; set; }
    public string Email { get; set; }
    public string PasswordHash { get; set; }
    public string Role { get; set; }
    public Guid? NetworkId { get; set; }
    public DateTime CreatedAt { get; set; }
}
```

`IUserCredentialStore.FindByCredentials` e `IAuthService.Authenticate` passam a ser assíncronos.

## 3. Especificação do Endpoint / Serviço

- Rota: `POST /api/v1/auth/login` (já existente, anônima).
- 200: token e perfil, como hoje.
- 400: corpo inválido (`VALIDATION_ERROR`).
- 401: credenciais inválidas (`AUTH_INVALID_CREDENTIALS`).

Tabela `users`: `id` gerado pela aplicação (`ValueGeneratedNever`), `email` único, `password_hash`, `role`, `network_id` nulo, `created_at` preenchido com `TimeProvider` na carga. `CHECK`s de papel e de coerência do `network_id`, válidos em SQLite e PostgreSQL.
