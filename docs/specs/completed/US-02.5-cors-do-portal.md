## 1. Contexto & Regras de Negócio

- O portal e a API ficam em hospedagens diferentes. O navegador só chama a API se a resposta liberar a origem do portal.
- As origens permitidas vêm de `Cors:AllowedOrigins`. Em Development a lista traz `http://localhost:5173`. Em produção a lista vem do ambiente (`Cors__AllowedOrigins__0`).
- Origem ausente da lista não recebe `Access-Control-Allow-Origin`.
- Uma entrada que não seja uma origem absoluta `http` ou `https`, sem caminho, consulta ou fragmento, impede a inicialização com `Configuração inválida`.
- Lista vazia não libera nenhuma origem. A API continua respondendo a chamadas sem cabeçalho `Origin`.
- O token segue no cabeçalho `Authorization`. A policy não usa credenciais de cookie.
- O contrato do `POST /api/v1/auth/login` não muda.

## 3. Especificação do Endpoint / Serviço

- A policy vale para toda a API, inclusive o preflight `OPTIONS`.
- Métodos liberados: `GET`, `POST`, `PUT` e `DELETE`.
- Cabeçalhos liberados: `Authorization` e `Content-Type`.
- `UseCors` fica antes de `UseAuthentication`.
